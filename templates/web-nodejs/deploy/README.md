# `deploy/` — what gets shipped to Kubernetes

This folder is the project's **Helm chart**. `tilt up` and `rda promote` both render it; the rendered manifests are what your cluster sees.

## Contents

| File | What it is | Who edits it |
| --- | --- | --- |
| `Chart.yaml` | Chart metadata + dependency on the SUSE library chart. | Touch only when bumping the library. `rda upgrade` does it for you. |
| `values.yaml` | Project values — DSL `services[]`, ingress block, image, port. **The source of truth for everything that varies between environments.** | You. Often. `rda add-service` updates this. |
| `templates/` | Empty by design. The library chart provides the Deployment / Service / Ingress / binding-secret templates; you don't need your own. Drop project-specific templates here only if the library doesn't cover your case. | Rarely. |
| `.rda/values.generated.yaml` | Generated overlay — the DSL `services[]` projected into chart-specific values (e.g. `postgresql.auth.username` from `services[].auth.user.name`). Helm reads this alongside `values.yaml`. | **Never** — it's regenerated by `rda render` (which the Tilt extension runs at every `tilt up`). Listed in `.gitignore`. |
| `charts/` | Vendored SUSE library chart (populated by `rda new`). Helm dep update can re-pull when you `rda upgrade`. | Never directly. |

## Why `deploy/` and not `chart/`

This directory used to be called `chart/`. Renamed because *"chart"* gives no hint about what to do with it — it sounds like an arbitrary helm chart we'd publish to a registry. **Calling it `deploy/` makes the purpose obvious to a newcomer cloning the repo: this is what gets deployed.**

Older projects scaffolded before bundle 0.11.13 still use `chart/`; `rda` and the Tilt extension auto-detect both names so no migration is required. New scaffolds use `deploy/`.

## Don't put app source here

App source lives at the project root (`src/`, `package.json`, etc.). `deploy/` is *only* the deployment surface. If you find yourself reaching for source code from a chart template, that's a signal to either drop the template or move the logic to the app — the library chart's Deployment renders your image, it doesn't run app logic at chart-render time.
