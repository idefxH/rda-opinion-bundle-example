## Prerequisite for the local Postgres

The bundled local Postgres runs from `dp.apps.rancher.io/containers/postgresql`
(SUSE Application Collection). Authenticate once with your AppCo / SUSE
Customer Center credentials before the first `tilt up`:

```bash
docker login dp.apps.rancher.io
```

Without this, the postgres pod gets `ErrImagePull` for an unauthenticated
registry. Once logged in, Rancher Desktop / Docker reuses the credentials
across rebuilds.

## What's inside

- `src/index.js` — Express server. Reads database credentials from
  `$SERVICE_BINDING_ROOT/database/` (Kubernetes Service Binding
  Specification). Returns service info on `/`, health on `/health`,
  readiness on `/ready`.
- `Chart.yaml` + `templates/` — Helm chart that deploys this app, a
  local Postgres sidecar, and the Service Binding secret wiring them
  together. Templates inlined from the SUSE library chart for v0;
  future versions will reference the library via `dependencies:`.
- `Tiltfile` — inner-loop config. Builds the app image, installs the
  chart, port-forwards `:8080` for the app and `:5432` for the
  Postgres sidecar.
- `Dockerfile` — multi-stage build on SUSE BCI Node.js 22. When the
  SUSE-AppCo buildpacks ship, you can drop this file and switch to
  `pack build`.

## Switching the database to a managed instance

Edit `values.yaml`:

```yaml
services:
  database:
    type: postgresql
    provider: external
    secretName: prod-payment-db-binding
```

Provision the Secret in the target namespace following the Service
Binding Specification keys: `type`, `provider`, `host`, `port`,
`username`, `password`, `database`. Typical sources: CloudNativePG,
Crossplane composition, manual Fleet manifest.
